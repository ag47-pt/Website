## 1. The Unit of Evolution

In traditional systems, the unit of progress is the "Sprint" or the "Commit". 
In the AG47 Evolution Protocol, the fundamental unit of progress is the **Evolution Cycle**.

An Evolution Cycle is a complete, self-contained traversal of the cognitive pipeline:
from perception of reality (`OBSERVING`) to the extraction of permanent knowledge (`LEARNING`).

If a cycle fails before `LEARNING`, no evolution occurred. A cycle is atomic: it either results in a validated state transition, a confirmed `no_op` (nothing to do), or a rollback to the original state.

## 2. State Ownership & Artifact Lifespan

The Evolution Protocol distributes ownership strictly to prevent agents from validating their own existence or reality.

### Cycle Ownership
The **Kernel (via Loop Manager)** owns the Evolution Cycle. 
No agent can start, stop, or rewind a cycle. Agents are merely invoked at specific states and return artifacts to the Kernel.

### Reality Ownership
The **Observer** owns the baseline truth.
When the Observer generates a `system-snapshot`, that snapshot is the unquestionable truth for the duration of the cycle.
If the Executor changes reality, the cycle is not closed until the Observer takes a **post-execution snapshot**, officially establishing the new baseline. The `LEARNING` phase seals the cycle, using this new snapshot as the end-state.

### Intention Ownership
The **Planner** owns the intent (`proposed-changeset`). 
The Executor cannot invent intent. The Validator cannot question intent. The Planner defines *what* and *how*.

### Verdict Ownership
The **Validator** owns the truth of execution. 
The Executor cannot declare success. The Validator confirms it through physical and behavioral evidence.

## 3. The Structure of a Cycle

Every cycle possesses an `evolution-cycle.json` record that acts as its DNA.
This record contains:
- **Trigger:** Why did this cycle start? (Scheduled, Manual Intent, Event-Driven).
- **State Machine:** Current state and retry counters.
- **Artifacts:** Pointers to the specific JSON artifacts generated by the agents in this cycle.
- **Agents:** The exact versions of the agents that ran this cycle (for determinism and audit).

## 4. Closing the Loop

A cycle is only closed when it hits a terminal state:
- `COMPLETED`: Execution succeeded, validated, and knowledge was optionally extracted. The final snapshot is taken.
- `FAILED`: Maximum retries exhausted or catastrophic protocol violation. Rollback enforced if necessary.

An open cycle implies the system is actively mutating or stuck. The Kernel must never allow overlapping open cycles on the same workspace boundary.
